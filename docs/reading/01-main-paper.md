# 主论文笔记：利润、期限与实例保留

核查日期：2026-09-29。本文是自写阅读解释与实现约定，不是论文原文、作者代码或实验结果；不代表任何读者已完成个人理解验证。

**原始来源：** Zhang 等，*Profit Maximization of Delay-Sensitive, Differential Accuracy Inference Services in Mobile Edge Computing*，IEEE Transactions on Mobile Computing，24(7):6209–6224，2025-07。[作者 PDF](https://www.cs.cityu.edu.hk/~weliang/papers/ZLXJY25.pdf)、[DOI](https://doi.org/10.1109/TMC.2025.3540017)。下文使用印刷页码，PDF 第 1 页为 6209。

## 1. 问题：为什么保留一个闲置实例可能有价值？

**解释。** 一个请求指定模型、最低准确率和期限。服务需要选择节点及模型分辨率；高分辨率通常更准，也更慢、更占资源。已有实例能避免创建等待，但闲置实例会占用其他请求所需的容量。保留与释放因此影响未来接纳机会。

**证据。** §III-A–C，页 6211–6212；§V-A，页 6216。请求为 `(源节点, 数据量, 模型, 最低精度, 期限)`；动态场景按具体实例的连续空闲时隙数决定释放。§VI-A 与 Fig. 7 已比较 θ=2/4/8/16 及不同期限范围。

**疑问。** 相同访问频率下，精度要求与期限如何配对，会不会改变某档实例的保留价值？原文分别给出这两个字段的取值范围，没有明确其联合分布；不能据此断言作者采用独立采样。

**实现影响。** 实例必须有节点、模型、分辨率、ID 和空闲计数器。θ 不是全局模型热度参数。准确率来自配置表，不是运行神经网络测得的预测准确率。

原文 k=1 表示最高精度，Tables II/III 的列却按 240p→720p 排列；采用原文下标时，映射为 k=1/2/3/4 → 720p/480p/360p/240p。表中相邻档资源有相等值，不能依正文严格递减的文字假设改动表值。

## 2. 问题：接纳收入和端到端延迟怎样计算？

**解释。** 暖实例的延迟包含上传、路径传输和推理；新实例还需创建时间。利润是付款减去上传、链路传输及推理费用。创建时间影响可行性，原文没有另设创建货币费或闲置保留费。

**证据。** §III-C，页 6212，Eq. (1)–(4)：

```text
delay = volume / upload_rate + volume × path_unit_delay + inference_time
payment = ψ(model, minimum_accuracy, deadline)
cost = ξ × volume / upload_rate + volume × path_unit_cost + inference_cost
profit = payment - cost
```

**疑问。** §VI-A 说精度和期限各分四档收费，但未提供完整边界与价格表。ξ 在正文是单位时间上传成本，实验段却描述为单位 Mbps 资源成本，量纲不一致；`log` 的底数也未明确。

**实现影响。** 公开收费表属于项目人为配置，各策略完全共享；不标为作者默认值。统一单位后再计算：MB/Mbps 转为 ms 时使用 `8000 × volume_MB / rate_Mbps`，SINR 的 dB 转线性值。若将 ξ 按单位上传时间解释，配置须写明货币/时间单位。新增启动费或闲置费用应另列扩展目标。

## 3. 问题：Algorithm 2 怎样选择新实例或已有实例？

**解释。** 原始利润高不一定值得接纳；对偶量相当于随着资源需求累积而增加的“机会成本”。算法比较两类折减利润，只接纳最高得分为正的候选。

**证据。** §V-B–C，页 6216–6218，Eq. (31)/(32)、(39)–(42) 与 Algorithm 2：

| 候选类型 | 独立可行条件 | 得分 | 获胜后的更新 |
| --- | --- | --- | --- |
| new | 标称精度达标；基础延迟 + 创建延迟 ≤ 期限 | `profit - s × α[j]` | 仅更新选中节点的 α，按 Eq. (41) |
| existing | 标称精度达标；基础延迟 ≤ 期限；时隙开始已有实例数 n≥1 | `profit - β[j,m,k]` | 仅更新该节点、模型、分辨率的 β，按 Eq. (42) |

对偶量在每次时隙调用开始时置零。Eq. (41) 使用 `s / Cᵗ[j]`；Eq. (42) 使用 `1 / (L × nᵗ[j,m,k])`。不得为追求形式一致自行改变分母。

**疑问。** 印刷伪代码与公式有两个冲突：第 6–7 行要求 N、E 同时满足并同时加入，Eq. (31)/(32) 却分别定义；第 15 行只检查 `(j,k)∈N`，会丢失在交集中真正获胜的分支。

**实现影响。** 本项目以 Eq. (31)/(32) **独立构造**候选，保留 `(mode, node, model, resolution, score)`，再联合 argmax；按获胜 mode 更新对应对偶量。这是公式指导的解释，不是逐字执行伪代码。并列规则、空集合直接拒绝、非正得分拒绝等边界应固定公开。不能用动态贪心代替后仍称 Algorithm 2。

## 4. 问题：时隙内新建实例会改变后续得分吗？

**解释。** 原算法输入的是时隙开始的状态快照。算法的逻辑分配与物理实例管理属于不同层次。

**证据。** §V-B，页 6216：

```text
Cᵗ[j] = C[j] - Σ nᵗ[j,m,k] × s[m,k]
```

Algorithm 2 没有逐请求改写 Cᵗ/nᵗ，也没有把本时隙新建实例加入已有候选集合。Eq. (21) 的新分配容量按请求摊分，右侧带 L；每实例最多服务 L 个同类请求。

**疑问。** 伪代码没有完整规定新分配怎样组成物理实例、已有实例的具体槽位分配和下一时隙 ID 的继承。

**实现影响。** 每个 slot 冻结 Cᵗ/nᵗ；新分配按 `(节点, 模型, 分辨率)` 分组，物理新实例数为 `ceil(该组新接纳请求数 / L)`。分组创建也不能让后续 new 请求免除原式中的创建延迟。具体实例使用与计数更新采用确定映射，记录为实现约定。

## 5. 问题：预置底座与空闲淘汰怎样共存？

**解释。** 正文的普通实例会在连续闲置达到阈值后释放；实验又要求保留预置实例以避免零分母。两者的衔接没有完整交代。

**证据。** §V-A 与 §VI-A，页 6216、6220。Nmax 包含 `1/(L × nᵗ)`；实验对 Algorithm 2/No_control 给出各档至少一份预置实例。是否逐节点预置、是否淘汰后补回，原文未明确。

**疑问。** θ 的两处文字边界有差异；最后一份实例是否允许淘汰？No_pre 为零预置，却没有完整给出 Nmax/b 的除零处理。

**实现影响。** 项目采用**每节点、每模型、每分辨率一份常驻 floor** 的解释，θ 只淘汰额外实例；未使用的额外实例计数加一、使用后置零，达到 θ 在槽末释放。所有保留规则共享底座与初始计数器。Table III 四档资源为 `0.5/0.5/1/1` 模拟 vCPU，三个模型的底座为 **9 模拟 vCPU/节点**；它不是本机物理核数要求。No_pre 和 No_control 的解释须独立命名，不默默补零或借用底座。

## 6. 问题：容量会严格满足吗？能继承竞争比吗？

**解释。** 原文动态算法允许有界资源违反；它并不是无条件的严格容量调度器。逻辑请求配额和 ceil 分组后的物理资源还可能不同。

**证据。** 页 6218–6219，Eq. (43)、Lemma 6 与 Theorem 2。Eq. (21)/(34) 带 `L × Cᵗ`，Eq. (41) 及证明部分出现 `Cᵗ`，L 因子一致性仍待澄清。φ₁/φ₂、Rmax、Nmax 的定义遍历全时域；理论还需要非零分母及正的利润下界等条件。

**疑问。** 这些界怎样在不知道未来请求和状态时获得？改变底座、单位解释或实例映射后，原证明是否仍适用？目前没有新的证明。

**实现影响。** 界从公开配置范围事先推导并固定，不能扫描测试轨迹求界。分别报告逻辑配额与物理容量的违反次数/幅度。加硬拒绝的版本另称 hard-cap 变体。**本项目不继承或宣称验证原文竞争比**，也不把补充解释称为作者实现。

## 7. 问题：什么证据才支持项目结论？

**解释。** 参数化 CPU 仿真能检验调度机制，不能测真实网络延迟或模型准确率。能运行一条命令与原式正确对应也是不同验收层级。

**证据。** §VI-A，页 6220；原实验使用 NetworkX、20 节点、50 时隙，模型参数由 Tables II/III 提供。Fig. 7 已研究 θ 与期限范围，保留阈值敏感性本身不是新问题。

**疑问。** 若轨迹全程只用常驻 floor，θ 是否根本没有被触发？重新配对改变 ψ 时，利润差是输入价值变化还是策略变化？

**实现影响。** 先以手工例核验暖/冷分支、mode、更新、ceil、TTL 和账本，再比较共享轨迹的策略差值。保存潜在付款、实际收入、费用分项、合格服务比例、实例事件与违反量。没有结果时只保留假设，不填写预设提升数字。后续问题与查新见 [相关工作](../related-work.md) 和 [决策记录](../decision-log.md)。
